# v2.4.5 정비 내역과 실기 확인

기준: v2.4.4 (51131a4). 패키지와 기존 서명을 유지하며 삭제 없이 업데이트한다.

## 파일 정리

- 자정 기준 00–02, 02–04 … 고정 2시간. 개인별 분할 선택은 제거하고 녹음 휴식 시간표는 유지한다.
- 새 녹음의 파일명에 시간 구간의 epoch 키를 남겨 재시작·복구·수동 정지·내보내기로 나뉜 조각을 다시 찾는다.
- 같은 구간의 호환 AAC-LC/16kHz/모노 패킷을 시각순으로 복사한다. 재인코딩하지 않는다. 비트레이트가 달라도 AAC 설정이 호환되는지 실제 트랙 정보를 검증한다.
- 뒤늦게 복구된 조각이 이미 합친 녹음의 중간 시각에 위치해도 패킷 순서를 다시 정렬하고 재생 위치를 재계산한다.
- 하루 TXT는 날짜별 한 개. 녹음이 없었던 구간에 무음을 삽입하거나 대화 내용을 추정하지 않는다.
- 파일 검증(패킷 수, 단조 증가 재생 시각, 전체 압축 음성 SHA-256) → 타임로그 교체 → 목록 교체 → 완료 기록 → 원본 정리 순서. AtomicFile 영수증으로 중단된 단계를 재시도한다.
- AI 공유 준비·개별 재생/공유 중인 이전 파일은 최대 24시간 보호한다. 준비한 음성과 TXT는 뒤의 병합으로 변하지 않는다. 개정 파일의 URI가 달라져 이전 전송 확인을 새 파일의 전송 완료로 오인하지 않는다.
- 기존 버전의 시간 구간 키 없는 녹음 및 외부 선택 폴더는 소급 병합·삭제하지 않는다. 소유자/경로/파일명 확인이 실패하거나 시각이 겹치면 원본을 보존하고 설정에 정리 보류 사유를 표시한다.
- 2시간은 실제 시각 범위이며 재생 길이가 아니다. PCM 시각 매핑과 AAC 프레임·인코더 지연 때문에 샘플 수준의 정확한 시각은 보장하지 않는다.

## 배터리와 메모리

- 마이크 입력이 없을 때 고정 10ms 반복 확인 대신 남은 50ms 프레임 분량을 기준으로 기다린다. 50ms RMS, VAD 기준·600ms 프리롤은 유지한다.
- 오디오 모드 조회는 최대 초당 5회로 합치고 경로 점검은 경과 시간 기준 1초 간격으로 실행한다.
- PCM 캡처 버퍼와 12개 프리롤 버퍼를 재사용한다. 초당 20개의 1,600바이트 캡처 배열을 새로 만들던 누적 할당을 줄인다. 이는 누적 할당량이며 실제 상주 메모리 절감 수치가 아니다.
- 홈의 시각 반응은 최대 10fps 유지. 설정·기록·휴식·마이크 대기에서는 1초 확인, 화면이 숨겨지면 웹 상태 확인 중단. 파형 데이터는 홈에서만 전송한다.
- 같은 상태 변화에 목록을 두 번 갱신하던 부분을 통합한다. 시작 시각 문자열과 오늘 파일 수를 캐시한다.
- 내보내기 타임로그 메타데이터를 파일마다 날짜 전체를 재탐색하던 방식에서 요청당 한 번 탐색으로 변경한다.
- 저장/병합 작업은 오디오 스레드와 분리된 낮은 우선순위에서 실행한다. 패킷마다 타임로그를 처음부터 순회하지 않고 이진 검색을 사용한다.
- 공유 준비 캐시는 녹음 자동 삭제 설정이 꺼져 있어도 24시간 경과 시 정리한다. 사용자 녹음 보관 기간과 별개다.
- 마이크와 PARTIAL_WAKE_LOCK은 녹음 유지에 필요하므로 임의로 제거하지 않는다. 검증된 백그라운드 서비스·WebView 우선순위와 휴식 알람을 유지한다.

## 크기와 남는 비용

v2.4.4 디버그 APK: 10,177,896바이트(약 9.71MiB), 웹 본체 약 62KiB. 가장 큰 항목은 classes.dex 약 8.24MiB이며 UI 이미지나 웹 프레임워크가 주된 용량 원인은 아니다.

사용하지 않는 Capacitor Filesystem 의존성, 웹 녹음용 Base64 저장 브리지, 예전 취침/포켓 모드 브리지, 미사용 내보내기 브리지와 중복 아이콘 배경을 제거했다. 최종 APK 크기는 실제 산출물로 비교한다. 기능이 없어진 코드의 삭제가 배터리 절감으로 바로 이어진다고 보지는 않는다.

병합에는 파일 읽기·검증·쓰기 비용과 임시 저장 공간이 든다. 24kbps를 무음 제거 없이 2시간 저장하면 압축 음성만 약 21.6MB이며, 원본·임시 결과·공유 중인 이전 판이 동시에 존재하면 그보다 많은 공간이 필요하다. RAM에는 음성 전체를 올리지 않으며 최대 16개 입력과 64KiB 패킷 버퍼를 사용한다. 디버그 설치 용량과 실제 실행 RAM·배터리는 서로 다른 지표다.

## 실기 체크

1. 같은 구간에서 녹음 정지/재시작 3회, 강제 종료 후 복구 → 최종 한 파일, 전후 음성 재생, 타임로그 재생 위치 확인.
2. 2시간 경계를 넘긴 통화·카메라·음성메시지 → 자동 재개, 구간별 정리 확인.
3. 녹음 중 내보내기 후 같은 구간 추가 녹음 → 새 개정 파일, 기존 공유 파일/고정 TXT 유지, 새 전송 확인 필요 표시.
4. 녹음 휴식 겹침·자정·화면 꺼짐 후 재개와 직접 정지 우선 확인.
5. 같은 기기/음질/VAD/네트워크/화면 조건에서 이전 버전과 각각 4–6시간 방전 비교, 이후 24시간 확인. 충전·화면 사용·통화·발열·실제 저장 길이를 함께 기록한다. 절감률은 아직 측정하지 않았다.

GitHub Actions에 Android 가상 기기 통합 테스트를 추가했다. 실제 AAC 생성, 압축 음성 병합, 전체 디코딩, 뒤늦은 중간 조각 복구, 고정 공유 파일 유지까지 검사한다. 가상 기기 검사와 갤럭시 실기의 통화·배터리 검증은 구분한다.

휴식 종료 후 실제 입력이 확인되면 재개 알림이 발송되도록 보류 상태가 초기화되던 조건을 수정했다. 하루 기록 목록에는 관리 대상 파일의 2시간 구간을 표시하고, 병합 개정으로 이전 전송 확인이 만료된 경우 새 녹음 안내를 표시한다.
