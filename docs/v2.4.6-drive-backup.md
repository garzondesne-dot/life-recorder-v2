# v2.4.6 — Google Drive 자동 백업

기준: v2.4.5 ae4eec3. 기존 앱 ID와 고정 서명, 기존 녹음·설정을 유지한다. main에 직접 커밋하거나 병합하지 않는다.

## 동작

- 기본 꺼짐. 설정의 고지에 동의하고 Google 계정 권한을 허용해야 켜진다.
- 앱이 저장 완료한 소유 녹음과 하루 TXT만 휴대전화→Drive로 업로드한다. 외부 선택 폴더는 제외한다. 기존 소유 녹음도 보관 기간 안이면 포함된다.
- 현재 2시간 파일은 마감·저장 이후 업로드한다. 녹음 중인 원시 저널을 스트리밍하지 않는다. 같은 2시간 구간의 새 병합본은 동일 Drive ID의 새 내용으로 갱신한다. TXT도 날짜별 동일 ID를 갱신한다.
- 경로: LifeRecorder/기기모델-기기ID앞8자리/YYYY-MM-DD. 부부가 같은 계정을 사용해도 서로의 파일을 덮어쓰거나 지우지 않도록 기기를 분리한다.
- 앱 시작·저장 완료·병합 완료·정리 요청 시 작업을 요청하고, 네트워크 연결 조건의 WorkManager가 처리한다. 누락 보완은 최소15분 주기의 주기 작업으로 요청한다. Android 절전·백그라운드 정책·강제 중지·네트워크에 따라 지연되며 엄밀한 실시간 보장은 없다.
- 1MiB 청크 재개 업로드. 세션과 사전 생성 Drive ID를 앱 내부 AtomicFile에 먼저 기록한다. 응답 유실 후 재시도도 동일 ID를 사용한다. 서버 MD5·크기를 검증한다. 토큰은 저장/웹 전달/로그 출력하지 않는다.
- 같은 구간의 조각이 미병합 상태로 여러 개면 해당 구간 업로드를 보류한다. 모든 조각 중 하나만 골라 Drive 원본을 덮어쓰지 않는다.
- 업로드 중에는 해당 녹음 한 개의 고정 임시 복사본을 사용한다. 병합/로컬 정리와 네트워크 I/O가 서로 막지 않도록 파일 복사만 공통 잠금에서 처리한다.
- 최신 파일 내용이 변하지 않았으면 재업로드하지 않는다. 작업이 없으면 주기 확인에서 Google API를 호출하지 않는다.

## 보관·삭제

- 기존 없음/2/7/15/30/60일을 휴대전화와 연결된 Drive 파일에 공동 적용한다. 오늘을 포함한 로컬 달력 날짜 기준이며 구간 마지막 녹음 날짜가 남아 있으면 보존한다.
- Drive 삭제는 **영구 삭제**이다. 앱 표식과 설치별 기기 표식·논리 파일 키가 일치하는 ID만 삭제한다. 사용자의 일반 Drive 파일·다른 기기 자료는 건드리지 않는다.
- 로컬 파일이 이미 없어도 계정별 백업 영수증의 날짜로 Drive 만료 삭제를 이어간다. 오프라인 동안 기간이 지난 미전송 파일을 뒤늦게 올리지 않는다.
- 직접 로컬 삭제는 Drive 즉시 삭제로 전파하지 않는다. Drive 직접 삭제·수정도 로컬로 가져오지 않는다. 자동 보관 만료만 양쪽에 적용된다.
- 연결 해제는 업로드와 Drive 정리를 중단하고 이미 올라간 파일은 남긴다. 같은 계정 재연결 시 내부 영수증을 재사용한다. 계정을 바꾸면 이전 계정 정리 권한은 사용하지 않는다.
- 앱 삭제/데이터 초기화 시 설치 ID와 영수증이 사라진다. 그 이후 이전 Drive 파일 자동 정리는 보장하지 않으므로 직접 정리가 필요하다. 원격 파일은 자동 삭제하지 않는다.
- 앱이 강제 중지되거나 삭제되었거나 장기간 오프라인이면 원격 정리도 지연된다. Google 계정 접근 동의가 취소되면 재연결해야 한다.
- Google Drive 자체의 버전 이력·휴지통·서비스 보관 정책과 로컬 파일 삭제는 서로 다르다. 이전 음성 버전은 Drive 서비스가 보관할 수 있다.

## Google Cloud 최초 설정 (필수)

이 설정을 완료하지 않은 상태에서 로그인 성공을 주장하지 않는다. 연결된 ChatGPT Drive 권한은 APK OAuth 설정을 대신하지 않는다.

1. Google Cloud Console에서 이 앱 전용 프로젝트 생성/선택.
2. APIs & Services → Library → Google Drive API 사용 설정.
3. Google Auth Platform에서 앱 이름·지원 이메일·개발자 연락처 설정.
4. Audience는 두 사람 시험 사용이면 External / Testing, 두 Google 계정을 Test users에 추가.
5. Data Access에 https://www.googleapis.com/auth/drive.file 추가. 전체 Drive scope는 요청하지 않음.
6. Clients → Create client → Android. 패키지명 `com.lifeblackbox.recorder`, 고정 keystore의 SHA-1 등록.
7. SHA-1은 Actions `Compile, lint and build APK` 단계의 `signingReport`에서 확인. 또는 로컬 `keytool -list -v -keystore keystore/debug.keystore -alias androiddebugkey -storepass android`.
8. Android OAuth 클라이언트에는 서버 client secret을 앱에 넣지 않는다. API 키/서비스계정 JSON/웹 OAuth secret도 필요 없다.
9. 설정 반영 후 APK의 Google 계정 연결로 실제 권한 창·업로드·재연결 확인.

현재 고정 debug 키는 테스트용이다. 공개 배포 전 별도 릴리스 서명/Play App Signing 인증서의 OAuth 등록과 업데이트 경로를 검토한다.

## 검증

- 기존 JS 문법/녹음 시작·정지/길게 누르기/공유 스냅샷/프롬프트/이력 테스트.
- Android 패치 멱등성, 권한·Google auth/WorkManager 의존성 각1개, 기존 서명 유지.
- Robolectric 가짜 Drive 전송: 응답 유실 중복 방지, 청크 재개, 병합본 같은 ID 갱신, 로컬 삭제 후 원격 만료 처리, 만료 파일 업로드 금지, 표식 불일치 삭제 금지, 계정 격리, 중단 가드.
- 기존 저장·복구·시간표·정리·2시간 병합 테스트와 실제 AAC 에뮬레이터 통합 테스트.
- Google OAuth 설정과 실제 계정 권한/Drive 서버 통신은 실기 검증 대상. 에뮬레이터의 모의 전송 테스트로 실제 로그인 성공을 대체하지 않는다.
